# 解决方案架构与数据契约

## 1. 逻辑架构

解决方案分为六层，各层都可以离线实现，避免把当前研究项目包装成不存在的在线产品。

### L1 数据接入层

职责：读取公开数据集、平台导出文件、研究采集结果或客户提供的脱敏样本，并映射为统一字段。

输入示例：CSV、JSON、Parquet。

输出：标准化评价记录、用户侧统计记录、评价对象记录和采集批次元数据。

### L2 数据质量层

检测：

- 主键和时间字段是否合法；
- 分数是否落在允许范围；
- 必填字段是否缺失；
- 是否存在完全重复或近似重复；
- 来源、采集时间和批次是否可追溯；
- 字段含义和单位是否一致；
- 是否存在明显的抽样偏差或覆盖缺口。

质量不合格的数据可以被隔离，但不能静默删除。

### L3 特征与证据层

建议按五类组织特征：

1. 数据质量：缺失、重复、冲突、字段合法性；
2. 行为信号：评价频率、突发程度、历史稳定性、极端分数比例；
3. 内容信号：长度、信息量、模板化、重复度、语义相似度；
4. 群体与时序：与稳健共识的偏差、同步行为、时间集中度；
5. 来源与上下文：数据来源、采集批次、对象热度、样本规模。

所有特征必须记录定义、方向、取值范围、缺失处理和计算版本。

### L4 评分与分级层

至少保留三类实现用于比较：

- 可解释规则基线；
- 统计/无监督异常检测；
- 有监督模型（仅在标注充分时使用）。

最终输出应包含分数、等级、置信度、风险标签、主要贡献证据和模型版本。

### L5 策略与稳健聚合层

评分不能直接等同于业务处罚。策略层将模型输出映射为：

- `ACCEPT`：正常使用；
- `DOWNWEIGHT`：降低聚合权重；
- `REVIEW`：进入人工复核；
- `QUARANTINE`：暂不参与关键决策；
- `INSUFFICIENT_EVIDENCE`：证据不足，等待更多数据。

聚合结果至少比较原始均值与可信度加权结果，量化解决方案带来的实际影响。

### L6 评估与展示层

展示内容应围绕决策闭环，而不仅是图表集合：

- 数据来源和质量；
- 可信等级分布；
- 风险类型及影响；
- 典型样本的解释；
- 原始聚合与修正聚合对比；
- 模型性能、稳定性和限制；
- 阈值改变带来的处置量变化。

## 2. 最小输入数据契约

评价级最小字段：

| 字段 | 类型 | 必需 | 说明 |
|---|---|---:|---|
| `record_id` | string | 是 | 评价唯一标识 |
| `subject_id` | string | 是 | 被评价对象标识 |
| `user_id_hash` | string | 否 | 脱敏用户标识；缺失时不可计算历史行为 |
| `rating` | number | 是 | 原始评分 |
| `rating_scale_min` | number | 是 | 量表下界 |
| `rating_scale_max` | number | 是 | 量表上界 |
| `review_text` | string | 否 | 评价文本；缺失时不可计算内容特征 |
| `created_at` | datetime | 否 | 评价时间；缺失时不可计算时序特征 |
| `source` | string | 是 | 数据来源 |
| `collected_at` | datetime | 是 | 采集时间 |
| `batch_id` | string | 是 | 可复现批次标识 |

字段缺失必须转化为能力缺失和置信度下降，不得用虚构值补齐。

## 3. 特征注册表契约

每个特征必须具备：

```json
{
  "feature_name": "rating_burst_24h",
  "version": "1.0.0",
  "entity": "review",
  "definition": "评价对象在24小时窗口内的评分集中程度",
  "direction": "higher_risk",
  "range": [0, 1],
  "missing_policy": "mark_unavailable",
  "required_fields": ["subject_id", "created_at"],
  "leakage_risk": "low"
}
```

## 4. 评分原则

### 可解释性

每个等级至少提供三个信息：主要正向证据、主要风险证据、缺失证据。不能只输出一个不可解释的分数。

### 校准

如果输出概率或置信度，需要用独立验证集检查可靠性曲线、Brier Score 或 ECE。未经校准的分类器分数不应称为真实概率。

### 阈值选择

阈值应根据误报成本、漏报成本和人工审核能力选择，并在验证集上冻结。禁止用测试集反复调阈值后再报告测试结果。

### 不确定性

样本少、字段缺失、分布漂移或模型外推时，应输出不确定性或拒绝判断。

## 5. 评估指标

### 有可信标签时

- Precision、Recall、F1；
- PR-AUC，特别适合风险样本占比较低的情况；
- ROC-AUC；
- 混淆矩阵；
- 校准误差；
- 按数据来源、时间、对象热度分组的性能。

### 无可信标签时

- 异常样本人工命中率；
- 规则一致性；
- 合成异常注入检出率；
- 重采样稳定性；
- 时间外验证；
- 聚合结果对高影响异常的敏感性。

无标签实验只能证明“发现统计异常的能力”，不能直接证明“识别恶意评价的准确率”。

## 6. 数据划分

优先采用按时间或评价对象分组的划分，避免同一用户、同一对象或高度相似文本同时进入训练集和测试集形成泄漏。

建议：

- 训练集：模型学习；
- 验证集：特征、超参数和阈值选择；
- 测试集：最终一次性报告；
- 时间外/来源外集合：评估迁移能力。

## 7. 治理与伦理

- 用户标识采用不可逆或受控的脱敏 ID；
- 不采集与目标无关的个人信息；
- 不使用种族、性别、宗教等受保护属性；
- 风险分数只作为审核证据，不自动作出不可逆处罚；
- 保存数据来源、许可、采集时间和删除要求；
- 对模型版本、阈值变更和人工复核保留审计记录；
- 对公开网站采集遵守站点规则、许可和合理频率。

## 8. 部署形态

当前推荐“离线批处理解决方案”：

```text
输入文件 → Python 评估流水线 → 结果文件/报告 → 本地 Web 展示
```

它与研究项目匹配，容易复现，也不需要虚构在线服务能力。后续试点再增加 REST API、数据库、权限和任务队列。
